## Context

A task carries a title and a free-text `notes` field, and that is the whole of
its history. There is nowhere to record "chased this again today" without
overwriting what was there before. This issue adds an append-only comment thread
per task.

Comments are private to this feature: an in-memory store held inside
`src/Taskboard.Api/Features/Comments/`, keyed by `TaskItem.Id`. The feature reads
the board to check that a task exists, but **never writes to it** - comments live
in your store, not on the `TaskItem` record, and `TaskItem` does not gain a
field. Nothing else in the repo reads or writes your store, and this feature
reads nothing another feature produces.

Read `AGENTS.md` before starting, especially "The domain". The rules there
override anything you would otherwise infer from this issue.

## Scope

Create exactly these folders and put every file you write inside them:

- `src/Taskboard.Api/Features/Comments/`
- `tests/Taskboard.Api.Tests/Features/Comments/`

You own exactly these routes and no others:

```
GET    /tasks/{taskId}/comments?limit=<int>&offset=<int>
POST   /tasks/{taskId}/comments
GET    /tasks/{taskId}/comments/{commentId}
PATCH  /tasks/{taskId}/comments/{commentId}
DELETE /tasks/{taskId}/comments/{commentId}
```

`/tasks` and `/tasks/{taskId}` belong to `area:tasks` and are already
implemented. Your routes are safe because every one of them carries the literal
`comments` segment - keep it that way, and do not map a catch-all. See the route
ownership table in `AGENTS.md`.

The store lives in your own folder. A `static readonly ConcurrentDictionary`
keyed by task id is the obvious choice, and concurrency safety matters because
these endpoints mutate. Do not use a database, a file on disk, or a service
registered in the root DI container.

`ApiFactory.ResetBoard()` resets the tasks and lists. It does **not** know about
your store, and you may not change it. Write tests that do not depend on
execution order: comment on a different task per test, or assert relative to what
that test itself created, rather than assuming your store starts empty.

Get timestamps from the injected `TimeProvider`, never from `DateTime.UtcNow`.

The **only** permitted edit to a shared file is the single registration line in
`src/Taskboard.Api/Program.cs`:

```csharp
    Features.Comments.CommentsFeature.Register(app);
```

placed in alphabetical position inside the `FEATURE REGISTRATION` block. No other
file outside your two folders may change - in particular not `Domain/**`,
`Store/**`, `Directory.Packages.props`, `Contracts/SharedContracts.cs`,
`Configuration/AppConfig.cs`, `Routing/**`, `Errors/**`, `.editorconfig`,
`ApiFactory.cs`, `StoreTests.cs`, `SmokeTests.cs`, or either implemented
feature's folder. If you believe you need such a change, stop and say so in the
PR.

Do not add NuGet packages.

## Interface

`src/Taskboard.Api/Features/Comments/CommentsFeature.cs` exposes exactly one
public member, with exactly this signature:

```csharp
namespace Taskboard.Api.Features.Comments;

internal static class CommentsFeature
{
    public static void Register(IEndpointRouteBuilder routes);
}
```

A comment is a type local to your feature:

```json
{
  "id": "01J9ZK0000000000000000000",
  "taskId": "renew-passport",
  "author": "mike",
  "body": "Chased the passport office again.",
  "createdAt": "2026-09-11T09:14:02.117+00:00",
  "editedAt": null
}
```

- `id` is generated by the server, is URL-safe, and is unique across every task's
  thread. `Guid.CreateVersion7().ToString()` is a fine choice - it sorts by
  creation time, which the ordering rule below wants anyway. It is never supplied
  by the caller.
- `author` is required on create, trimmed, 1-40 characters.
- `body` is required on create, trimmed, 1-2000 characters.
- `createdAt` is UTC. `editedAt` is `null` until the comment is patched.

Behaviour:

- `GET /tasks/{taskId}/comments` responds `200` with `Page<T>` from
  `Taskboard.Api.Contracts`, ordered by `createdAt` ascending then `id` ordinal
  ascending. Paging goes through `PageRequest.From`. A task with no comments
  returns an empty page, not a `404`.
- `POST /tasks/{taskId}/comments` responds `201` with the created comment and a
  `Location: /api/tasks/{taskId}/comments/{id}` header.
- `GET /tasks/{taskId}/comments/{commentId}` responds `200`, or `404` when either
  the task or the comment is unknown, or when the comment exists but belongs to a
  different task.
- `PATCH /tasks/{taskId}/comments/{commentId}` edits the `body` only and responds
  `200` with the updated comment and a non-null `editedAt`. `author`, `id`,
  `taskId` and `createdAt` are not editable; a body attempting to change one is a
  `400`.
- `DELETE /tasks/{taskId}/comments/{commentId}` responds `204`, and `404` when it
  is already gone.
- Every route validates the task first: an unknown `taskId` is `404` with
  `code` = `NOT_FOUND`, and the check goes through `ITaskStore.Find` rather than
  a hard-coded list of ids.

## Acceptance criteria

- `POST /api/tasks/renew-passport/comments` with
  `{ "author": "mike", "body": "Chased them again." }` returns `201`, a server-
  generated `id`, `taskId` = `"renew-passport"`, a UTC `createdAt`, `editedAt`
  = `null`, and a `Location` header pointing at the new comment. Following that
  `Location` returns `200` with the same comment.
- `author` and `body` are trimmed, and a missing, null, empty or whitespace-only
  value of either returns `400` with `code` = `BAD_REQUEST`. So does an `author`
  over 40 characters or a `body` over 2000.
- An `id` or `taskId` supplied in the create body is ignored or rejected, never
  honoured.
- `GET /api/tasks/{taskId}/comments` returns the comments that test created, in
  `createdAt` order, with a correct `total`, `limit` and `offset`, and pages
  correctly. An out-of-range `limit` or a negative `offset` returns `400`.
- A task with no comments returns `200` with `items: []` and `total: 0`.
- Posting to, listing, fetching, patching or deleting under an unknown task id -
  `/api/tasks/no-such-task/comments` - returns `404` with `code` = `NOT_FOUND`
  in every case.
- Fetching a real comment id under the wrong task id returns `404`, not the
  comment. A test asserts this with two comments on two different tasks.
- `PATCH` with `{ "body": "..." }` returns `200`, the new body, an unchanged
  `author` and `createdAt`, and an `editedAt` that is not null. `PATCH` with an
  empty object, an unknown field, or an attempt to set `author`, `id`, `taskId`
  or `createdAt` returns `400`.
- `DELETE` returns `204`, and a second `DELETE` of the same comment returns
  `404`. The comment no longer appears in the list.
- Deleting the **task** is out of scope: comments are not cascaded, and no test
  asserts that they are.
- Nothing in the feature mutates a `TaskItem`, a `TaskList`, or anything returned
  by a store.
- Timestamps come only from the injected `TimeProvider`, and configuration only
  through `IOptions<AppConfig>`.
- Tests live in `tests/Taskboard.Api.Tests/Features/Comments/`, carry
  `[Collection(ApiCollection.Name)]`, drive the app through `ApiFactory`, cover
  each bullet above, and pass regardless of the order tests run in.
- `dotnet test Taskboard.slnx` and
  `dotnet format Taskboard.slnx --verify-no-changes` both pass.
- The diff touches only `src/Taskboard.Api/Features/Comments/`,
  `tests/Taskboard.Api.Tests/Features/Comments/`, and the one registration line
  in `Program.cs`.
